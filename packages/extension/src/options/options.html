Annot Settings
by ingcreators · Advanced capture options

Overlays

Hide fixed headers, stickies, and modals that repeat across scroll-capture segments.

Recommended. The first scroll-capture segment keeps the page's natural header, then the header is hidden from segment 2 onward so it doesn't repeat in the stitched image. Matches Shottr / Xnapper / CleanShot behavior.
Advanced: preserved selectors
Example: .toast, #cookie-banner — useful when a banner is part of the page you want to capture.

Scrollbars

Injects CSS to hide the browser's scrollbar so it doesn't appear in the captured image. Works in Chromium & Firefox.

Capture timing

Longer delays produce more stable captures on slow / animated pages.

Wait after scrolling before snapping each full-page / per-page segment.
Wait after each click before the shot (lets menus / tooltips render).
Usually kept short so the shot matches the exact moment the key fired.
Throttle between successive segments of scroll / per-page captures to avoid Chrome rate limits.

Image format

How captured images are encoded and stored.

Smart mode: palettizes crisp UI screens to PNG-8 (smaller AND sharper than JPEG), but automatically falls back for photo-heavy pages to avoid posterization.
If a sampled pixel scan finds more unique colors than this, the image is treated as photo-heavy and falls back. Default 15000: admin UIs / docs / code editors use PNG-8 for sharp text, while feed/photo-heavy pages fall back automatically. Lower to ~5000 for strict "flat UI only"; raise to ~30000 to force PNG-8 on most pages.
Used for "JPEG" format and the JPEG smart-fallback option. 85–95% is good for screenshots.

Viewport emulation Advanced

Capture at a specified output pixel size (e.g. Full HD 1920×1080) by physically resizing the browser window before the capture, then restoring it. The extension divides the target by your display's device-pixel-ratio (DPR) so the resulting image lands on the requested pixel dimensions.

⚠ The browser window will briefly resize during capture. If the target is larger than your monitor (after DPR compensation) it's clamped to what fits. Mobile UA emulation is not supported — use Chrome DevTools for that.
