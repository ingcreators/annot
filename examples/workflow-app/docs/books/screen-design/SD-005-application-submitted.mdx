# Application submitted — element spec

Route: `#/apply/submitted`. Component:
`<wf-application-submitted>`.

Guards:

- No user → `/login`.
- No `state.lastSubmittedId` (hard refresh / direct link) →
  `/menu`. The id is the only state this screen needs.

<Screen id="application-submitted" src="/shots/application-submitted.png">

<Overlay match={{ role: "heading", name: "Application submitted" }} intent="success" number={1}>
**Heading**

- Static text. Body sentence reads:
  "Your application has been forwarded for approval."
</Overlay>

<Overlay match={{ role: "button", name: "Back to menu" }} intent="action" number={2}>
**Back to menu**

- `data-testid`: `submitted-back-to-menu`.
- `navigate("/menu")`. The menu's history list now shows the
  new application at the top.
</Overlay>

</Screen>

## Application ID display

The new id is rendered inside `<strong data-testid="submitted-id">`.
Tests use the testid to assert on the assigned id (e.g.
`APP-004` after the seed `APP-001..003`).
